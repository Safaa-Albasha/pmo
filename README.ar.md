# pmo: مكتب إدارة مشاريع ذكي لـ Claude Code

[English](README.md)

plugin لـ Claude Code تعمل كمكتب إدارة مشاريع متوافق مع **دليل PMBOK® الإصدار الثامن** من PMI. تدعم المشاريع **التنبؤية (Waterfall) والرشيقة (Agile) والهجينة (Hybrid)**، وتكتب **بالعربية أو الإنجليزية**. القرار يبقى بيد مدير المشروع: الوكلاء يحللون ويكتبون المسودات، لكن أي تغيير على سجل محمي ينتظر موافقتك.

**ما الذي تقدمه:**
- **11 وكيلًا متخصصًا:** قائد مكتب إدارة المشاريع، والبدء، والتخطيط، والمراقبة المالية (EVM)، والمخاطر، والجودة، والتحكم بالتغيير، ومدرب Agile، والتقارير، والربط بالأدوات، والإغلاق.
- **محرّك حسابات دقيق:**
  - القيمة المكتسبة: SPI وCPI وEAC وETC وVAC وTCPI.
  - المسار الحرج مع توقع الانتهاء من التقدم الفعلي.
  - سرعة الفريق وAgileEVM.
  - تقييم المخاطر والقيمة النقدية المتوقعة والخريطة الحرارية.
  
  الأرقام كلها محسوبة، ولا شيء منها مُخمَّن.
- **تقرير تفاعلي:** ملف HTML واحد يعمل بدون إنترنت. يصلح لوحةً وعرضَ شرائح بملء الشاشة، وفيه تبديل بين العربية والإنجليزية، ووضع داكن وفاتح، وأشرطة "ماذا لو".
- **حوكمة:** مقترحات، وطابور موافقات، وسجل قرارات. ويمنع Hook التعديل المباشر على السجلات المحمية.
- **أدوات ربط (اختيارية):** Jira وConfluence، وAsana، وLinear، وmonday.com، وClickUp، وSlack، وMicrosoft 365، وGoogle Drive، وGmail. واستيراد من Excel وCSV لملفات MS Project وPlanner وغيرها.

> تحتاج **Node.js 18 أو أحدث** (https://nodejs.org) ولا شيء غيره.

## التثبيت

```bash
claude plugin marketplace add Safaa-Albasha/pmo
claude plugin install pmo@pmo
```

أعد تشغيل Claude Code، ثم افتح مجلد مشروعك وشغّل `/pmo:setup`.

الدليل الكامل خطوة بخطوة في **[INSTALL.ar.md](INSTALL.ar.md)**: يشرح تثبيت Node.js وClaude Code، وأول مشروع، وربط الأدوات، والتحديث، وحل المشاكل.

## البدء السريع

1. **أنشئ المشروع:** شغّل `/pmo:new` وأجب عن بضعة أسئلة (الاسم، والمنهجية، واللغة، والعملة، والتواريخ، والميزانية). سيُنشأ مجلد `.pmo/` داخل مجلدك.
2. **أضف خطتك:** إما أن تبنيها مع وكيل التخطيط (اكتب مثلًا "خطط المشروع")، أو تستورد ملفًا من Jira أو MS Project أو Excel عبر `/pmo:import`.
3. **كل أسبوع:** شغّل `/pmo:weekly`. يسجّل التقدم، ويشغّل كل الوكلاء، ويكتب تقرير الحالة، ويعرض عليك القرارات المطلوبة.
4. **القرارات:** شغّل `/pmo:approvals` لتوافق على مقترحات الوكلاء أو ترفضها أو تعدّلها.
5. **التقرير:** شغّل `/pmo:report` لبناء التقرير التفاعلي أو عرض اللجنة التوجيهية.

**جرّب أولًا على مثال جاهز:** انسخ أحد المجلدات `examples/waterfall` (عربي) أو `examples/agile` (إنجليزي) أو `examples/hybrid` إلى مجلد جديد، ثم شغّل `/pmo:status`. ويوجد تقرير جاهز للمعاينة في `examples/sample-report-waterfall.html`.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `/pmo:setup` | فحص الجاهزية وربط الأدوات |
| `/pmo:new` | إنشاء مشروع جديد (مجلد `.pmo/`) |
| `/pmo:status` | الصحة العامة 🟢🟡🔴، وSPI وCPI، والانتهاء المتوقع مقابل خط الأساس، والنقاط المنجزة والمتبقية، وأهم المخاطر |
| `/pmo:weekly` | الدورة الأسبوعية الكاملة مع كل الوكلاء، وإحاطة في شاشة واحدة |
| `/pmo:approvals` | البتّ في المقترحات المعلّقة، مع تسجيل كل قرار |
| `/pmo:report` | التقرير التفاعلي والعرض |
| `/pmo:risks` | سجل المخاطر، والخريطة الحرارية، وإضافة مخاطر أو تحديثها |
| `/pmo:change` | طلبات التغيير مع تحليل أثرها |
| `/pmo:sprint` | تخطيط السبرنت ومراجعته وإغلاقه (Agile وHybrid) |
| `/pmo:close` | إغلاق مرحلة أو المشروع كله، والدروس المستفادة |
| `/pmo:import` | استيراد ملفات CSV أو Excel أو JSON، بعناوين أعمدة عربية أو إنجليزية |
| `/pmo:sync` | سحب البيانات من الأدوات المربوطة |

تستطيع أيضًا أن تكتب طلبك بلغة عادية، مثل: "كيف حال المشروع؟" أو "أضف خطرًا عن التصاريح" أو "جهّز عرض اللجنة التوجيهية".

## كيف تعمل الموافقات

| المستوى | من يقرر | أمثلة |
|---|---|---|
| 🟢 تلقائي | الوكلاء | الحسابات، والتحليل، والمسودات، والتقارير، وتحديث الـ Backlog والقضايا والتقدم |
| 🟡 موافقتك | أنت، عبر `/pmo:approvals` | المخاطر، والجدول، والميزانية، وخط الأساس، والميثاق، وطلبات التغيير، وإغلاق المشروع، وأي كتابة أو رسالة إلى أداة خارجية |
| 🔴 ممنوع دائمًا | — | حذف السجلات، واختراع الأرقام، والإرسال بدون تأكيدك |

**خطوات الموافقة:**
1. يرسل الوكيل **مقترحًا** يوضح ما سيتغير، ولماذا، وما أثره.
2. توافق عليه أو ترفضه أو تعدّله.
3. ينفّذ المحرّك التغيير المعتمد بعد التحقق من سلامة المشروع كله.
4. يُسجَّل القرار في `.pmo/decisions.json` مع اسم من قرر ووقت القرار.

**الحماية:** يمنع Hook أي تعديل مباشر على الملفات المحمية، ويطلب Claude Code تأكيدك قبل كل تنفيذ لأمر الموافقة. هذه الحماية تعمل حتى في وضع تجاوز الصلاحيات (bypass). تحققنا من ذلك: عندما لا يمكن الحصول على تأكيد، يُرفض الأمر.

## بيانات المشروع (`.pmo/`)

| الملف | المحتوى | يتغير عبر |
|---|---|---|
| `project.json` | الاسم، والمنهجية، واللغة، والعملة، والتواريخ، وحدود الألوان | موافقة |
| `charter.md` | ميثاق المشروع | موافقة (من مجلد `drafts/`) |
| `schedule.json` | الأنشطة، والاعتمادات بينها، وخط الأساس | موافقة |
| `budget.json` | الميزانية عند الإنجاز، والاحتياطيات، ومنحنى القيمة المخططة | موافقة |
| `risks.json` · `changes.json` · `scope/wbs.json` | السجلات المحمية | موافقة |
| `scope/backlog.json` | السبرنتات وعناصر الـ Backlog | مباشرة |
| `progress/<date>.json` | نسبة الإنجاز، والتكلفة الفعلية، والنقاط المنجزة، وإنجاز كل نشاط | مباشرة |
| `issues.json` · `stakeholders.json` · `quality.json` · `lessons.json` | السجلات الأخرى | مباشرة |
| `approvals.json` · `decisions.json` | طابور الموافقات وسجل القرارات | المحرّك فقط |
| `drafts/` · `reports/` | المسودات والتقارير المولّدة | مباشرة |

**ملاحظات:**
- أحدث لقطة تقدم هي التي تحدد تاريخ الحالة، ونسب إنجاز الأنشطة فيها هي التي يُحسب منها توقع الانتهاء.
- كل الملفات JSON أو Markdown عادية. احفظ مجلد `.pmo/` في Git لتحصل على سجل تدقيق كامل.

## أدوات الربط

كلها اختيارية. بدونها يعمل كل شيء من الملفات المحلية والاستيراد.

| الأداة | طريقة الربط |
|---|---|
| Jira وConfluence، Asana، Linear، monday.com، ClickUp | خادم MCP رسمي يضيفه `/pmo:setup` لإعدادات المشروع، ثم يسجّل كل مستخدم دخوله بحسابه عبر `/mcp` |
| Slack، Microsoft 365، Google Drive، Gmail | موصلات claude.ai (من claude.ai: الإعدادات ثم الموصلات) |
| MS Project، Planner، أي جدول بيانات | التصدير إلى Excel أو CSV، ثم `/pmo:import` |

سحب البيانات يتم تلقائيًا، أما أي كتابة أو رسالة إلى أداة خارجية فتطلب تأكيدك.

## ملاحظات منهجية

- **هيكل PMBOK الإصدار الثامن:** 6 مبادئ، و7 مجالات أداء (الحوكمة، والنطاق، والجدول، والمالية، وأصحاب المصلحة، والموارد، والمخاطر)، و5 مجالات تركيز (البدء، والتخطيط، والتنفيذ، والمراقبة والتحكم، والإغلاق). المهارات مبنية على هذا الهيكل، وتكيّف الممارسات حسب المنهجية.
- **العملة:** يحددها مدير المشروع بحرية. يمكن أن تكون رمزًا دوليًا (ISO 4217)، فتظهر برمزها المحلي تلقائيًا (مثلًا KWD تظهر «د.ك»)، أو أي تسمية خاصة. لكل مشروع عملة واحدة، وتغييرها لاحقًا يحتاج موافقة، ولا يحوّل المبالغ تلقائيًا.
- **الأيام:** الجدول يحسب بالأيام التقويمية، وتاريخ الانتهاء محسوب ضمن المدة.
- **التقدير عند الإنجاز (EAC):** يُعرض بثلاث طرق من PMI.
- **درجة الخطر** = الاحتمال × الأثر، كلاهما على مقياس من 1 إلى 5. الخطر عالٍ إذا كانت درجته 15 فأكثر، ومتوسط إذا كانت 6 فأكثر.

**تنبيه:** النص التحليلي في التقارير يكتبه الذكاء الاصطناعي، أما الأرقام في الجداول والرسوم فمصدرها المحرّك. راجع النص قبل إرساله لأصحاب المصلحة.
